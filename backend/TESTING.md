# Проверка backend

Проверено 23 сентября 2026 года локально на Apple M3 Pro, macOS arm64, Go 1.25.7, PostgreSQL 16.2. PostgreSQL запущен отдельным временным кластером в `backend/.tmp`, без изменения существующих баз пользователя.

## Выполненные команды

Из папки `backend`, с `TEST_DATABASE_URL`, указывающим на временный PostgreSQL:

```sh
make test          # go test -race -cover ./...
make check         # форматирование и go vet ./...
make build         # оба бинарника
make catalog-check
make benchmark
docker compose config --quiet
```

Все перечисленные проверки прошли. Интеграционный тест PostgreSQL **выполнен**, не пропущен. Race detector не обнаружил гонок. Дополнительно запущены собранные `bin/catalog bootstrap` и `bin/server`, выполнены `scripts/smoke.sh`, HTTP-проверки контрольных сценариев и 100 повторов одного запроса.

Проверена конфигурация Docker Compose. Сборка и запуск контейнеров не выполнялись: Docker daemon в окружении не был запущен. Сборка Go, миграции, импорт и HTTP-сценарии проверены нативно с настоящим PostgreSQL.

## Покрытие проверок

- CSV: UTF-8/BOM, кавычки и переводы строк, флаги, null часов, неизвестные справочники, повреждённые строки, пропавшие/дублирующиеся столбцы, дубли ID, некорректные/бесконечные числа, диапазон дат, пустой каталог.
- Аудит: 66 профилей, 17 категорий, распределение городов 50/15/1, флаги 13 synthetic / 18 price_imputed / 8 city_imputed, 9 null часов, 13 мультикатегорий.
- Подбор: контрольная воронка 10 → 9 → 7 → 7 → 7 → 4, равные цена/бюджет и длительность/лимит, все причины исключения, пропуск optional-полей, нормализация Unicode/casefold, перестановки профилей, отсутствие дублей.
- Для каждого профиля и каждой его категории построены запросы на все 100 дат календаря. В каждой выдаче проверены принадлежность пулу, соблюдение условий и инварианты счётчиков; проверка включает площадки.
- Объяснения: специфичность top-3, два предложения, календарная дата, проверяемые цитаты, отказ при устаревшем хеше/неподтверждённой цитате, показ условия аренды от трёх часов. Шаблон продолжает работать без фактов, инструкции в description не влияют на подбор или ответ.
- HTTP: типы, обязательные поля, null, лишние/повторные ключи, дробный/экспоненциальный бюджет, переполнение, неверные дата/enum, лишний JSON, лимит тела, Content-Type, 404/405, CORS, справочники, health/readiness/metrics, безопасный 503.
- PostgreSQL: два запуска миграций, повторный импорт без дублей, точный round trip, откат некорректного ввода, откат ошибки INSERT после DELETE, 60 HTTP-запросов параллельно с пятью импортами, обнаружение ручной порчи данных, восстановление импортом, 503 после закрытия пула БД.

Покрытие инструкций при `go test -race -cover ./...`: загрузчик 89,5%, HTTP 95,7%, подбор 94,4%, PostgreSQL 73,3%. Это пакетные значения стандартного Go coverage; CLI дополнительно проверена запуском собранных бинарников.

Онлайн-LLM не реализован и не требуется. Проверен независимый шаблонный путь; теста таймаута внешнего LLM-вызова нет, поскольку такого вызова в приложении нет.

## Задержка

100 последовательных HTTP POST к собранному серверу через loopback, прогретый процесс, чтение настоящего PostgreSQL на каждый запрос, без внешнего LLM:

| Показатель | Миллисекунды |
|---|---:|
| p50 | 3,389 |
| p95 | 3,564 |
| Максимум | 3,949 |

Показатели измерены на стороне HTTP-клиента и относятся только к этому локальному прогону. Они не являются нагрузочным SLA для удалённого развёртывания. Ориентир задачи в 10 секунд соблюдён с запасом.

Отдельный Go benchmark только подбора и объяснений, без БД и HTTP: около 0,142 мс/операцию (141638 ns/op, 8518 итераций).

## Повторная проверка

```sh
docker compose up -d db
export TEST_DATABASE_URL='postgres://hackalem:hackalem_local@127.0.0.1:54329/hackalem?sslmode=disable'
make test
make test-integration
make check build
```

Интеграционный тест создаёт уникальную схему `hackalem_test_<id>`, удаляет её после выполнения и не меняет существующие таблицы. PostgreSQL должен уже работать; тест не запускает его самостоятельно. Без `TEST_DATABASE_URL` обычный `make test` пропустит интеграционный тест, а `make test-integration` завершится ошибкой конфигурации.

## Альтернативы NO_MATCH — 23 сентября 2026

База: `edcc4377edce3f22202f58f9b6121dcbda1fbbc2` (свежий GitHub main).
Каталог из `data/` импортирован в отдельную локальную PostgreSQL-базу:
66 профилей, 68 фактов, версии совпадают с указанными выше.

- AT-04: Алматы / Ведущий / корпоратив / 2026-11-14 / 100000 ₸ / русский / 6 ч:
  обычный endpoint — `NO_MATCH`; минимальная BUDGET — **650000 ₸**, eligible_count=1.
  Число 4 относится к исходному acceptance-запросу с бюджетом 1000000 ₸,
  а не к минимальному бюджету. Минимальность проверена также на 649999 ₸.
- Сканированием импортированного календаря найден сценарий: те же город,
  категория, формат, язык и часы, бюджет 650000 ₸, **2026-09-24** — `NO_MATCH`
  с причиной `BUSY_ON_DATE`; DATE — **2026-09-25**, distance_days=1,
  eligible_count=1. Независимая BUDGET для исходной даты — 900000 ₸,
  eligible_count=1. Оба сценария закреплены в unit, HTTP и PostgreSQL tests.
- `go test ./...`, `go test -race ./...`, `go vet ./...` и
  `TEST_DATABASE_URL=… make test-integration` прошли. PostgreSQL tests выполнены,
  не пропущены; существующие acceptance expectations не изменены.
- curl подтвердил 200/NO_MATCH старого endpoint, ответы BUDGET/DATE нового,
  422 для невалидного запроса и 400 для некорректного JSON. При первом локальном
  вызове альтернатив: AT-04 — 17.6 мс, DATE — 4.7 мс, включая PostgreSQL.
  HTTP 503 проверен с недоступным source и закрытым PostgreSQL pool.
- Unit tests проверяют минимальность, фактическую применимость одного изменения,
  сохранность входных данных, запрет объединения альтернатив, tie в пользу +1,
  обе границы и всё окно, пустые ответы, NO_CATALOG, MATCHES_FOUND,
  optional-поля, детерминизм и независимость от порядка каталога.
  HTTP tests проверяют точный JSON, общий формат ошибок, один snapshot на запрос,
  методы, local CORS и неизменную схему `/api/recommendations`.

БД и проверяет равенство всех не локализуемых полей ответа для трёх языков.
