# Панель администратора Apex AI

Адрес: [testrr.shop/admin/](https://testrr.shop/admin/). Отдельное приложение на Go + PostgreSQL, HTML/CSS/JS встроены в бинарник. Использует общую базу с `backend`: сохранённые изменения сразу видны публичному API подбора.

## Возможности

- Вход администратора, обязательная смена временного пароля, выход и смена пароля.
- Поиск и фильтры каталога, ручное добавление, редактирование и удаление подрядчиков.
- CSV: предварительная проверка, число новых и существующих ID, образец записей. По умолчанию только новые ID. Обновление существующих — с отдельной галочкой; без неё конфликт отменяет всю загрузку.
- Экспорт каталога, скачивание шаблона, журнал последних 50 изменений.
- Атомарные операции и контроль версии предотвращают перезапись изменений другого администратора.

CSV должен соответствовать исходной схеме из 13 колонок; разделитель — запятая, наборы внутри ячеек — `|`, кодировка UTF-8. Лимит multipart-запроса 5 МиБ и 5000 записей за загрузку. Весь файл проверяется перед сохранением. Импорт не удаляет отсутствующие в файле записи. Даты занятости ограничены календарным окном каталога.

ID неизменяемый, 1–80 латинских букв, цифр, `_` или `-`, первый символ — буква или цифра. Удаление требует подтверждения в интерфейсе; последнюю запись удалить нельзя. При изменении описания удаляются связанные старые подтверждённые факты; новые факты автоматически не генерируются.

## Локальный запуск

Все команды раздела выполняются из `admin_panel`. Нужны Go 1.25+, PostgreSQL и уже инициализированный каталог (см. [backend/README.md](../backend/README.md)). Сервис админки отсутствует в Compose backend и запускается отдельно. Модули находятся рядом: `go.mod` использует `replace ../backend`.

```sh
cp .env.example .env
# Отредактируйте DATABASE_URL под локальную БД.
set -a
. ./.env
set +a
make build
bin/admin init
bin/admin serve
```

Открыть http://127.0.0.1:18081/admin/. `init` создаёт таблицы и пользователя `admin`, печатает случайный временный пароль один раз. Сохраните его. Общего стандартного пароля нет. После первой смены пароля войдите заново. Повторный `init` не меняет существующий пароль. Можно задать `ADMIN_INITIAL_PASSWORD` только на время первой инициализации. Пароли не включаются в репозиторий.

При первом входе нужно сменить пароль: минимум 12 символов, максимум 72 байта. После смены все сессии отзываются и требуется повторный вход. Пароли хешируются bcrypt; cookie HttpOnly, Secure в production, SameSite=Strict; срок сессии 8 часов. Изменения защищены Origin и CSRF. Вход и смена пароля ограничены 10 попытками за 15 минут на IP в памяти процесса.

## Окружение

Пример локальной конфигурации — [.env.example](.env.example), серверной — [deploy/admin.env.example](deploy/admin.env.example). `.env` автоматически не загружается: экспортируйте значения перед запуском. Production получает окружение через systemd.

| Переменная | Значение по умолчанию и назначение |
|---|---|
| `DATABASE_URL` | Обязательна; та же БД, что у публичного backend |
| `ADMIN_ADDR` | `127.0.0.1:18081`; адрес прослушивания |
| `ADMIN_ORIGIN` | `https://testrr.shop`; точные схема, хост и порт, без пути и завершающего `/` |
| `ADMIN_INSECURE_HTTP` | По умолчанию выключено; значение `true` разрешено только для loopback-адреса и origin |
| `ADMIN_TRUST_PROXY` | По умолчанию выключено; `true` доверяет `X-Real-IP` только от loopback и требует loopback listener |
| `ADMIN_INITIAL_PASSWORD` | Необязателен, только первая инициализация; без него генерируется случайный пароль |
| `TEST_DATABASE_URL` | Только тесты; отдельная тестовая БД с правом CREATE схем |
| `TEST_FIXTURE_DIR` | Только тесты; путь к исходному каталогу, если он недоступен по стандартному относительному пути |

Для локального примера откройте именно `http://127.0.0.1:18081/admin/`: `localhost` — другой origin. В production `ADMIN_INSECURE_HTTP=false`; HTTP между Nginx и loopback-сервисом не требует отключения Secure-cookie, поскольку браузер работает по HTTPS.

## Сценарий модерации

1. Войдите и при необходимости смените временный пароль.
2. Найдите запись в списке, откройте редактирование или создайте новую. Сохранение сразу меняет рабочий каталог; отдельного одобрения публикации нет.
3. Для CSV скачайте шаблон/экспорт, заполните данные и выполните предпросмотр. Проверьте новые/существующие ID и образец первых 8 записей.
4. Разрешайте обновление существующих записей только если нужна полная замена их полей. Импорт без этой галочки отклоняется целиком при любом совпавшем ID.
5. Если каталог изменился параллельно, обновите список/предпросмотр и проверьте ввод снова. Нельзя автоматически повторять запись со старой revision.
6. Повторите поиск в публичном интерфейсе и проверьте журнал изменений. Уже показанная выдача не обновляется автоматически.

Preview не блокирует каталог и не сохраняет файл: при импорте файл отправляется и проверяется заново. Изменения записываются в общую PostgreSQL, а не в CSV репозитория. Аудит фиксирует автора, действие, ID и версии; он не хранит прежний профиль целиком и не позволяет отменить действие одной кнопкой.

### Формат CSV

```text
id,anon_name,categories,city,city_imputed,synthetic,price_from_kzt,price_imputed,event_formats,languages,max_hours,busy_dates,description
```

Списки: `Ведущий|Ведущий церемонии`, `русский|английский`; даты: `2026-11-14|2026-11-15`. Ячейки с запятыми, кавычками и переводами строк должны быть заключены/экранированы по правилам CSV. `max_hours` может быть положительным дробным числом или пустым; поле формы меняется с шагом 0,5 часа, API валидирует положительное конечное число. Пустые занятые даты допустимы.

CSV-экспорт содержит только текущие профили. Он не сохраняет метаданные окна, факты, пользователей, сессии и аудит; для полного backup нужен PostgreSQL dump. CLI backend `import/bootstrap` полностью заменяет каталог и может стереть модерацию — при обычном обновлении админки эти команды не запускаются.

### Ограничения

- Нет управления пользователями/ролями, MFA, черновиков, очереди публикации и отмены по аудиту.
- Смена описания удаляет устаревшие подтверждённые факты; панель не создаёт новые автоматически.
- Календарное окно не редактируется через панель.
- Добавленные города/категории видны в API meta, но публичный frontend пока использует встроенные справочники.
- Публичный подбор возвращает первые три подходящих профиля по цене и ID; отсутствие карточки в top-3 не означает, что её исключил фильтр.
- Список загружается целиком, поиск/фильтры выполняются в браузере; серверной пагинации нет.

## Проверки

```sh
TEST_DATABASE_URL='postgres://user:password@127.0.0.1:5432/testdb?sslmode=disable' make test check
```

Каждый интеграционный тест создаёт отдельную схему и удаляет её после завершения. Роль должна иметь CREATE на тестовую БД. Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. `check` запускает gofmt, go vet и `node --check` (нужен Node). Покрыты авторизация, принудительная смена пароля, сессии, CSRF, CRUD, импорт, конкурентные изменения, откат транзакций и журнал. Для отдельно собранного тестового бинарника путь к данным можно задать через `TEST_FIXTURE_DIR`.

Полная матрица автоматических и ручных проверок: [TESTING.md](TESTING.md). Наличие теста в коде не означает его выполнение: интеграционные проверки требуют `TEST_DATABASE_URL`.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| 401 | Сессия истекла или пароль изменён; войдите заново |
| 403 `ORIGIN_REJECTED` | Адрес браузера должен точно совпадать с `ADMIN_ORIGIN` |
| 403 `CSRF_REJECTED` | Обновите страницу и сессию; не используйте старый токен |
| 403 `PASSWORD_CHANGE_REQUIRED` | Завершите смену временного пароля |
| 409 `REVISION_CONFLICT` | Обновите каталог/preview и повторно проверьте действие |
| 409 `DUPLICATE_ID` | Для новой записи нужен уникальный ID; для CSV обновление разрешается явно |
| 428 | Клиент не передал `If-Match`; получите актуальную revision |
| 429 | Достигнут лимит попыток; повторите после указанного `Retry-After` |
| 503 | Проверьте общую БД, исходный каталог, выполнение `admin init` и локальный `/readyz` |

- `internal/app` — HTTP, авторизация, интеграционные тесты, встроенный интерфейс.
- `../backend/catalogadmin` — публичная библиотека общих правил каталога.
- `../backend/internal/postgres` — транзакционная работа со снимком каталога.
- [ENDPOINT.MD](ENDPOINT.MD) — все маршруты и формат данных.
- [deploy/README.md](deploy/README.md) — production и обслуживание.
