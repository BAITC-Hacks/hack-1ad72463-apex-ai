# Развёртывание

Production: https://testrr.shop/admin/. Сервис `hackalem-admin`, адрес `127.0.0.1:18081`, пользователь ОС `hackalem`; общий PostgreSQL с backend. Публичный доступ идёт через существующий nginx/TLS. Отдельный порт наружу не открывается.

## Сборка

Из папки `admin_panel` при наличии соседнего `backend`:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/admin-linux-amd64 ./cmd/admin
```

Поместите бинарник `admin` и документы в `/opt/hackalem/admin_panel/releases/<release>/`. Релизы принадлежат root, бинарник 0755. Симлинк `/opt/hackalem/admin_panel/current` указывает на активный релиз.

Перед первым запуском сделайте `pg_dump -Fc` существующей БД. Скопируйте `admin.env.example` в `/etc/hackalem/admin.env` (root:hackalem, 0640). Запустите init от пользователя hackalem с `DATABASE_URL` из этого файла. Сохраните напечатанный временный пароль в защищённом месте; он не записывается в env или git. `init` не импортирует и не заменяет существующий каталог.

Установите `hackalem-admin.service` в `/etc/systemd/system/`, затем:

```sh
systemctl daemon-reload
systemctl enable --now hackalem-admin
curl --fail http://127.0.0.1:18081/readyz
```

Скопируйте `hackalem-admin.conf` в `/etc/nginx/snippets/`; в HTTPS server block `testrr.shop` добавьте `include /etc/nginx/snippets/hackalem-admin.conf;`. Сохраните все текущие маршруты фронтенда и `/api`. Проверьте `nginx -t`, затем `systemctl reload nginx`.

## Обслуживание

```sh
systemctl status hackalem-admin
journalctl -u hackalem-admin -n 80 --no-pager
curl --fail https://testrr.shop/admin/
curl --fail https://testrr.shop/api/health
```

Обновление: создать новый каталог релиза, переключить current и перезапустить `hackalem-admin`. Откат бинарника — переключить current на прежний релиз и перезапустить сервис. Перед изменениями схемы сохраните резервную копию БД. Откат бинарника не откатывает редактирование каталога; восстановление данных выполняется отдельно из проверенной резервной копии. CLI backend `import/bootstrap` заменяет каталог целиком: не запускайте их при обновлении админки.

Временный пароль меняется при первом входе. Если пароль утрачен, восстановление выполняет оператор через SSH: остановить admin, удалить сессии и пользователя admin в одной транзакции, повторить init для новой временной учётной записи, затем запустить сервис. Это не затрагивает каталог или аудит. Резервные копии БД включают хеши паролей и сессии; храните их с правами 0600.

## Совместимость компонентов

Обновляйте исходники `admin_panel` и `backend` из совместимого коммита: админка собирается с `replace ../backend`. Файлы интерфейса встроены в бинарник, поэтому после изменения HTML/CSS/JS нужно пересобрать и заменить бинарник. Отдельного `npm build` для админки нет.

Первичная инициализация выполняется после загрузки каталога backend. При обычном обновлении достаточно сборки, нового релиза, переключения ссылки и перезапуска. `admin init` идемпотентно создаёт недостающие административные таблицы и пользователя, но не сбрасывает пароль; это не команда восстановления пароля. Публичный API продолжает читать ту же БД.

Сохраняйте три маршрута Nginx: `/` для frontend, `/api/*` для backend и `/admin/*` для админки. В [hackalem-admin.conf](hackalem-admin.conf) используется `location ^~ /admin/` и `proxy_pass` без URI: префикс `/admin/` должен дойти до сервиса. SPA fallback не должен отвечать на `/admin/api/*`. Nginx перезаписывает `X-Real-IP`; доверие прокси включается только для loopback-сервиса.

Приложение ограничивает multipart-запрос 5 МиБ, конфигурация Nginx — 6 МиБ. Nginx может вернуть собственную HTML-ошибку 413 до обработки запроса Go. `ADMIN_ORIGIN=https://testrr.shop` задаётся без пути `/admin/`; `ADMIN_INSECURE_HTTP=false` сохраняется даже при HTTP на внутреннем loopback-соединении.

## Проверка после обновления

На сервере:

```sh
nginx -t
systemctl is-active hackalem-admin hackalem-backend nginx
curl --fail http://127.0.0.1:18081/readyz
curl --fail https://testrr.shop/admin/
curl --fail https://testrr.shop/api/health
curl -sS -o /dev/null -w '%{http_code}\n' https://testrr.shop/admin/api/vendors
```

Последний запрос выполняется без cookie и должен вернуть 401. `GET /api/health` проверяет backend, а не admin. `/readyz` админки доступен только через локальный порт. Страница `/admin/` должна отдавать интерфейс входа; HTTP 200 от SPA сам по себе не подтверждает правильность маршрута.

Через браузер проверьте вход существующего администратора, просмотр каталога и публичный поиск. Сценарии создания, импорта, конфликтов и удаления выполняйте на тестовой БД по [TESTING.md](../TESTING.md). Не восстанавливайте полную старую Nginx-конфигурацию при откате одного компонента: можно потерять маршруты, добавленные другими обновлениями.

## Данные и резервные копии

- Изменения админки живут в PostgreSQL и не переносятся в Git или исходный CSV автоматически.
- Экспорт из панели содержит профили; он не включает факты, окно календаря, пользователей, сессии и аудит.
- Для полного восстановления нужен проверенный dump БД. Аудит показывает автора, действие и ID, но не хранит прежний объект целиком и не позволяет автоматически отменить запись.
- Откат релиза админки не возвращает удалённые профили. Восстановление данных — отдельная операция с учётом новых изменений и совместимости схемы.
- Пароли, cookies и дампы не добавляются в Git. Пример окружения не содержит действующих секретов.
