# Проверка админ-панели

Документ описывает существующие тесты и воспроизводимый порядок проверки. Обновление документации само по себе не является новым запуском интеграционных тестов. Исходники: [internal/app/server_test.go](internal/app/server_test.go).

## Автоматические проверки

Нужны Go 1.25+, Node.js для `node --check`, PostgreSQL и соседний модуль `backend`. Из `admin_panel`:

```sh
export TEST_DATABASE_URL='postgres://hackalem:hackalem_local@127.0.0.1:54329/hackalem?sslmode=disable'
make test check
```

Адрес выше подходит локальной БД из Compose backend. Используйте тестовую БД: тесты создают уникальную схему, загружают исходные фикстуры и удаляют собственную схему после завершения. Роли требуется CREATE схем. `make test` запускает `go test -race -cover ./...`; без `TEST_DATABASE_URL` тесты с PostgreSQL пропускаются. `make check` проверяет gofmt, go vet и синтаксис JavaScript. Если данные недоступны по стандартному пути, задайте `TEST_FIXTURE_DIR` на каталог с исходными CSV/JSON.

| Тест | Что проверяет |
|---|---|
| `TestAuthenticationAndSessionLifecycle` | 401 без сессии, Origin на login, неверные данные, принудительная смена пароля, CSRF, отзыв/истечение сессий, bcrypt |
| `TestCatalogCRUDImportAndAudit` | Создание/полное редактирование/удаление; ошибки CSRF/Origin/revision/ID/валидации; удаление устаревших фактов; preview без записи; отказ и явное обновление совпавших ID; экспорт/шаблон; аудит; откат при ошибке БД |
| `TestConcurrentMutationsAndLastRecord` | Одна из двух записей одинаковой revision получает конфликт; последний профиль удалить нельзя |
| `TestRateLimitAndProxy` | Лимит попыток, истечение периода, доверие X-Real-IP только loopback-прокси |

Публичный backend имеет отдельный Go-модуль и отдельные тесты: [backend/TESTING.md](../backend/TESTING.md). Успех тестов одного модуля не заменяет проверку другого. Точные ID и число 66 в фикстурах относятся к исходному набору, а не к текущему production-каталогу.

## Проверки работающего сервиса без изменения данных

```sh
curl --fail http://127.0.0.1:18081/readyz
curl --fail https://testrr.shop/admin/
curl -sS -o /dev/null -w '%{http_code}\n' https://testrr.shop/admin/api/vendors
curl --fail https://testrr.shop/api/health
```

Локальный readiness проверяется на хосте сервиса. Без cookie запрос к `/admin/api/vendors` должен вернуть 401. Страница входа должна открыться как HTML, а не как React SPA. `/api/health` подтверждает публичный backend; это не readiness админки. Проверяйте TLS обычным способом, без `-k`.

## Ручной сценарий на отдельном тестовом каталоге

1. Инициализировать каталог backend и выполнить `admin init`. Повторный `init` не должен менять пароль.
2. Войти с временным паролем; убедиться, что до смены доступен только соответствующий экран. Сменить пароль и войти заново.
3. Создать синтетический профиль с уникальным тестовым ID, корректной ценой, языками и датой внутри окна. Проверить новую запись и событие аудита.
4. Выполнить подбор через реальный публичный API той же тестовой БД. Состав зависит от фильтров и top-3; при необходимости подобрать параметры, при которых проверяемая запись входит в выдачу.
5. Открыть каталог в двух сессиях. Изменить запись в первой, затем попытаться сохранить старую версию во второй: ожидается 409 без потери первого изменения.
6. Подготовить CSV с новым и существующим ID. Preview должен показать оба вида и не менять каталог. Без разрешения обновления — 409 и полный откат; с разрешением — добавление/замена, остальные записи сохранены.
7. Изменить описание профиля с фактом: старое доказательство должно исчезнуть, объяснение по структурированным данным остаётся доступным.
8. Экспортировать каталог и проверить, что CSV читается общим парсером. Скачать шаблон из 13 колонок.
9. Удалить тестовую запись; проверить новый каталог и аудит. Удаление последней записи в специально подготовленной тестовой схеме должно быть запрещено.
10. Проверить выход, истечение сессии и повторный вход, а также переключение браузера между публичным frontend и `/admin/`.

Не используйте production для сценариев, меняющих данные. CSV-экспорт не заменяет полную резервную копию: в нём нет фактов, метаданных, пользователей, сессий и аудита. Диагностика ошибок и настройки окружения: [README.md](README.md).
